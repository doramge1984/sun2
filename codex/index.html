AGENTS.md가 뭐예요?

코덱스에게 주는 업무 지침서입니다.

  • 프로젝트 폴더 안에 두는 글자 파일(메모장으로 열립니다)
  • 코덱스는 일을 시작하기 전에 이 파일을 먼저 읽습니다
  • 그래서 질문할 때마다 규칙을 다시 말하지 않아도 됩니다

왜 “파일”로 넣나요?

웹 ChatGPT와 코덱스는 지침을 두는 곳이 다릅니다.

  • 웹 ChatGPT 프로젝트 → 지침 칸에 적습니다
  • 코덱스 프로젝트 → 폴더 기반이라 지침 칸이 없고, 폴더 안 AGENTS.md가 그 역할을 합니다
  • 같은 폴더를 쓰면 누구나 같은 지침으로 일합니다

어디에 두나요?

프로젝트 폴더 맨 위(01_신입QA 안)에 둡니다.

  • 파일 이름은 AGENTS.md 그대로 — 철자와 대소문자가 다르면 읽지 않습니다
  • 직접 만들 수도 있지만, 오늘은 코덱스에게 “만들어서 저장해줘”라고 시킵니다
  • 처음 받은 실습 자료에는 없고, 이 단계에서 새로 생깁니다

어떻게 쓰면 잘 듣나요?

네 가지만 담으면 됩니다.

  • 역할 — “신입 사원의 질문에 답하는 도우미”
  • 근거 범위 — “지식 파일에 있는 내용으로만” (① ②)

  • 답 형식 — 세 줄, 숫자 그대로, 안전 표시 (④ ⑤)

스킬 — 매주 같은 보고서를 같은 숫자로

규칙을 파일로 저장해 두는 레시피, 스킬을 만들어 매주 같은 보고서를 받습니다.

금요일마다 엑셀 5개에서 숫자를 옮겨 워드를 채우고, 회의에서 “이거 맞아요?”를 듣습니다. 규칙을 한 번 스킬로 저장해 두면 언제 불러도 같은 방식으로 일합니다. 프로젝트가 “방”이라면 스킬은 “레시피”입니다.

준비

압축을 푼 03_주간보고스킬 폴더(수주대장 · 생산일보 4개 · 주간보고_양식.docx · 참고_지난주_특이사항.md)를 코덱스에서 새 프로젝트의 폴더로 엽니다. 폴더 열기는 공정 1과 같습니다.

1단계 · 스킬 없이 만들어 보기

첨부한 수주대장과 라인별 생산일보로, 이번 주(10/5~10/9) 주간보고를 주간보고_양식.docx와 같은 항목 순서·표로 워드 파일로 만들어줘. 기준일은 10/9야. 특이사항은 참고_지난주_특이사항.md에서만 가져와.

워드 파일이 나오면 열어서 납기 현황과 라인별 달성률을 봅니다. 같은 프롬프트를 한 번 더 보내 숫자가 같은지도 비교해 보세요.

2단계 · 스킬로 만들기

아래 프롬프트를 보냅니다. 코덱스가 스킬 폴더와 계산 스크립트를 만들고, 저장한 위치와 부르는 방법을 알려 줍니다.

주간보고 작성 스킬을 만들어줘. 이름은 weekly-report-writer. 하는 일: 수주대장(xlsx)과 라인별 생산일보(xlsx·csv)에서 숫자를 계산해 주간보고_양식.docx와 같은 항목 순서·표로 워드 문서를 만든다. 특이사항은 내가 주는 메모(md)에서만 가져온다. 계산 규칙: 남은 일수 = 납기일 − 기준일, 0보다 작으면 지연, 0~3이면 임박(3 포함), 출하완료는 제외. 라인 달성률 = 실적 합 ÷ 계획 합, 90% 미만이면 미달(정확히 90.0%는 아님). 다음 주 납기 예정은 기준일 다음 날부터 7일. 만든 문서를 다시 읽어 상태별 건수와 라인 달성률을 계산값과 대조하는 검산까지 스크립트(scripts/build_report.py)로 해줘. 양식 파일은 스킬 폴더에 넣어줘. 설명(description)에는 "주간보고 만들어줘, 이번 주 보고서 써줘, 주간보고 양식대로"가 오면 쓴다고 적어줘. 다 만들면 스킬을 저장한 위치와 부르는 방법을 알려줘.

에이전트는 파일 두 가지로 만듭니다
  • .codex/agents/이름.toml · 담당 에이전트 한 명의 설명서입니다. TOML(톰)은 설정을 적어 두는 메모장으로 열리는 텍스트 파일로, 이름·한 줄 설명·일하는 방법·하면 안 되는 일이 적힙니다. 직접 쓰지 않고 코덱스가 만들어 주며, 사람은 열어서 확인만 합니다. 점(.)으로 시작하는 폴더는 탐색기에서 숨겨져 보일 수 있습니다.
  • AGENTS.md · 이 폴더에서 일하는 AI 전체가 따르는 지침. 총괄의 역할도 여기에 씁니다.

마음에 드는 디자인을 참고로 넣는 방법 3가지

말로 설명하기 어렵다면 마음에 드는 디자인을 보여 주고 “이 느낌으로” 바꾸게 할 수 있습니다.

① 디자인 설명 파일(DESIGN.md) 넣기

유명 사이트의 색, 글꼴, 간격, 버튼 모양을 글로 정리해 둔 DESIGN.md 파일을 공유하는 곳이 있습니다. 아래 사이트에서 마음에 드는 브랜드의 파일을 찾아 output 폴더에 넣고 요청합니다.

  • getdesign.md · 브랜드별 디자인 모음을 둘러보는 사이트입니다. 분위기를 보고 고르기 좋습니다.
  • github.com/VoltAgent/awesome-design-md · 같은 파일들이 들어 있는 GitHub 모음입니다. 원하는 브랜드 폴더의 DESIGN.md를 열어 내용을 복사해 메모장에 붙여 넣고 DESIGN.md라는 이름으로 저장하면 됩니다.

대시보드에는 Linear, Notion, Stripe, Vercel, Supabase처럼 깔끔한 업무 화면 브랜드가 잘 어울립니다. 파일은 공개 모음이라 무료로 쓸 수 있지만 사이트 운영 단체가 만든 것이 아닌 비공식 분석입니다. 사이트 구성과 메뉴는 바뀔 수 있습니다.

output/DESIGN.md의 디자인 방식을 참고해서 총괄대시보드.html의 디자인만 바꿔줘. 내용과 버튼 기능은 그대로 두고.

② 마음에 드는 웹페이지 캡처 넣기 (가장 쉽습니다)

마음에 드는 화면을 캡처해서 Codex 입력창에 붙여 넣거나 + 버튼으로 첨부한 뒤 요청합니다.

첨부한 이미지의 색과 분위기를 참고해서 총괄대시보드.html의 디자인만 바꿔줘. 로고나 문구는 따라 하지 말고, 내용과 버튼 기능은 그대로 두고.

③ 구글 이미지에서 찾아 쓰기

구글 이미지에서 대시보드 UI 디자인, 관리자 화면 디자인, dashboard UI처럼 검색하면 다양한 화면이 나옵니다. Pinterest, Dribbble 같은 디자인 모음 사이트도 좋습니다. 마음에 드는 이미지를 저장하거나 캡처해서 ②번처럼 넣습니다.

꼭 지켜 주세요
  • “느낌만 참고하고 로고, 문구, 이미지는 그대로 쓰지 마”를 함께 적습니다. 남의 사이트를 그대로 베끼면 저작권과 상표 문제가 될 수 있습니다.
  • “내용과 버튼 기능은 그대로”를 항상 함께 적어야 기능이 사라지지 않습니다.
  • Codex에게 “구글에서 찾아서 적용해줘”라고 시킬 수도 있지만 결과가 매번 달라집니다. 사람이 직접 고르는 편이 안정적입니다.

Sites로 게시하는 방법 보기

Codex가 만든 파일은 게시하지 않으면 외부 링크가 없습니다. 접속 링크가 필요할 때만 OpenAI의 Sites로 게시할 수 있습니다. 서버를 직접 준비하지 않아도 됩니다.

  1. Codex 왼쪽 세로 메뉴의 … (더 보기)를 누르고 사이트를 고르면 Sites를 열 수 있습니다. 또는 아래 요청 문장을 Codex에 바로 입력해도 됩니다. (웹: Sites 페이지)
  2. 대시보드 HTML을 첨부하거나, 데스크톱에서 기존 로컬 프로젝트를 바탕으로 사이트를 만들어 달라고 요청합니다.
  3. 먼저 미리보기를 확인합니다.
  4. 게시하고 방문할 수 있는 사람의 범위를 설정한 뒤 생성된 링크를 공유합니다.

요청 문장은 이렇게 쓰면 됩니다.

이 총괄대시보드를 Sites로 만들어줘. 먼저 미리보기만 만들고, 게시 전 내가 확인하게 해줘.
화면으로 따라하기 · 사이트 메뉴와 미리보기 만드는 중

왼쪽 세로 메뉴의 … (빨간 상자)를 누르면 프로젝트, 사이트, 지도 등이 보입니다. 요청을 보내면 Codex가 “Sites 스킬로 미리보기를 만들겠습니다. 게시 전 검토할 수 있도록 저장하고, 공개 게시하지 않겠습니다”라고 알리고 사이트를 만듭니다.

이미지를 누르면 새 창에서 크게 볼 수 있습니다.

게시하기 전에 알아 둘 점

  • 근거 링크가 data 파일을 가리키므로, 웹에서도 볼 수 있도록 근거 자료를 함께 구성해야 합니다.
  • 승인·반려·보류 선택은 지금 새로고침하면 초기화됩니다. 계속 저장하거나 여러 사람이 공유하려면 저장 기능을 추가해야 합니다.
  • 게시하면 접속할 수 있는 사람에게 내용이 보입니다. 실제 회사 자료는 올리지 말고, 방문할 수 있는 사람의 범위를 꼭 확인하세요.
  • Sites는 베타 기능이고 요금제와 사용량 한도가 있어, 계정에 따라 보이지 않을 수 있습니다.

공식 Sites 안내 · 혼자 확인할 때는 1번 또는 2번을 씁니다. Sites 게시가 잘 안 되면 바로 아래 4번의 외부 서비스로 배포하세요.

왜 하나요?

Sites 게시가 안 될 때도 대시보드를 웹 링크로 보낼 수 있습니다. HTML 파일 묶음은 무료 호스팅에 올리면 바로 주소가 생깁니다.

Netlifyapp.netlify.com/drop완성된 폴더를 끌어다 놓기빠르게 링크 만들기 (오늘 시연)

올리기 전에 꼭 확인하세요
  • 올릴 폴더를 따로 만드세요. 작업 폴더 전체를 올리면 AGENTS.md, 정답키 같은 파일도 함께 공개됩니다. 새 폴더에 data 폴더와 output 폴더만 복사해서 그 폴더를 올리세요. 대시보드의 근거 링크(../data/…)가 그대로 작동합니다.
  • 올린 폴더 맨 위에 index.html이 있어야 주소만으로 열립니다. 대시보드 파일이 output 안에 있으면 주소 뒤에 /output/총괄대시보드.html을 붙여 접속합니다. 더 간단하게 하려면 총괄대시보드.html을 복사해 이름을 index.html로 바꿔 맨 위에 두세요. (이 경우 근거 링크 경로가 맞지 않을 수 있습니다.)
  • 링크를 아는 사람은 누구나 볼 수 있습니다. 가상 데이터로 만든 연습용만 올리고, 실제 회사 자료는 올리지 마세요.

① Netlify에 폴더 올리기 · 가장 간단한 방법
  1. Netlify Drop에 접속하고 로그인합니다.
  2. 준비한 폴더를 업로드 영역에 끌어다 놓습니다.
  3. 배포가 끝나면 생성된 주소로 접속해 확인합니다.
  4. 수정했다면 업데이트한 폴더를 다시 올립니다.

업로드하는 폴더 바로 안에 index.html이 있어야 주소만으로 열립니다. 로그인하지 않고 올리면 사이트가 일정 시간 뒤 사라질 수 있으니 로그인한 상태로 올리세요. 공식 안내

② GitHub Pages로 배포하기
  1. GitHub(github.com/login)에 로그인하고, github.com/new에서 새 저장소(Repository)를 만듭니다.
  2. 준비한 폴더 안의 파일과 폴더를 저장소 맨 위에 올립니다.
  3. 저장소의 Settings → Pages로 들어갑니다.
  4. Source는 Deploy from a branch를 고릅니다.
  5. Branch: main / 폴더: /(root)로 정하고 저장합니다.
  6. 잠시 뒤 Pages 화면에 표시되는 주소를 공유합니다.

무료 계정은 저장소를 공개(Public)로 해야 Pages를 쓸 수 있습니다. 공식 안내

연수에서는 Netlify 폴더 업로드부터 해 보고, 수정과 관리까지 이야기할 때 GitHub Pages로 이어가면 이해하기 쉽습니다.

5. 회사에서 계속 쓰는 법 · 채팅에 뭐라고 하면 되나요

왜 하나요?

AI 팀은 한 번 만들어 두면 됩니다. 이후에는 새 자료를 폴더에 넣고, 채팅에 한두 줄만 치면 됩니다.

  1. Codex에서 내 업무 프로젝트를 엽니다. 새 채팅을 시작해도 됩니다.
  2. 이번에 처리할 실제 자료를 각 data/에이전트이름/ 폴더에 복사해 넣습니다. 그 에이전트가 읽을 자료만 넣습니다.
  3. 아래 요청을 차례로 입력합니다.
  4. 결과를 열어 근거를 확인하고, 대시보드에서 승인·반려·보류를 결정합니다.

처음 한 번 · 파일을 읽을 수 있는지 시험

data 아래 각 폴더의 파일을 읽을 수 있는지만 확인해줘. 파일마다 이름과 처음 세 줄만 보여주고, 못 읽는 파일은 알려줘. 아직 일은 시키지 마.

매번 · 일 시키기

총괄이 담당 에이전트에게 data의 새 자료로 일을 나눠 맡겨줘. 각자 자기 폴더의 자료만 읽고, 결과는 output에 저장한 뒤 총괄보고.md를 만들어줘.

매번 · 대시보드 새로 만들기

output의 새 결과로 총괄대시보드.html을 다시 만들어줘. 항목마다 근거, 승인·반려·보류 버튼, 반려 이유 칸을 넣어줘.
이렇게 하면 더 편해요
  • 결과가 덮어써지지 않게 “output 안에 오늘 날짜 폴더(예: 2026-10-16)를 만들어 저장해줘”라고 덧붙이세요.
  • 일을 시킨 뒤 “각 결과의 근거 파일과 줄 번호를 확인해서, 근거가 없는 항목은 알려줘”라고 한 번 더 점검하게 하세요.
  • 반려한 이유는 공정 5처럼 “이 이유를 바탕으로 에이전트 지침 변경안을 보여줘”로 팀에 되돌리면 다음 번에 더 좋아집니다.
  • 처리가 끝난 자료는 data 폴더 밖의 보관 폴더로 옮겨 두면 다음 자료와 섞이지 않습니다.

왜 하나요?

자료 종류이렇게 준비하세요
엑셀(xlsx)그대로 넣어도 됩니다. 시트가 많거나 서식이 복잡하면 필요한 시트만 CSV로 저장합니다. 첫 줄에 제목(열 이름)을 한 줄만 두고, 합친 칸은 풀어 주세요.

워드(docx)그대로 넣습니다. 표는 단순할수록 잘 읽습니다.
PDF글자가 드래그로 선택되는 PDF는 그대로 넣습니다. 스캔본은 글자가 틀릴 수 있으니 원본 파일(엑셀, 워드)이 있으면 그걸 쓰세요.

폴더에 넣기 전 6가지

  1. 에이전트마다 그 일에 필요한 파일만 넣습니다. 많이 넣는다고 좋아지지 않습니다.
  2. 파일 이름에 날짜와 내용을 넣습니다. 예: 2026-10_재고표.xlsx
  3. 한 파일에는 한 가지 주제만 담고, 아주 큰 파일은 나눠 넣습니다.
  4. 개인정보와 민감한 숫자는 지우거나 가립니다.
  5. 원본은 따로 두고 복사본을 넣습니다.
  6. 처음에는 1~2개 파일로 시험하고, 위의 “읽을 수 있는지 확인” 요청으로 확인한 뒤 늘립니다.

파일 형식에 따라 읽는 정도가 다를 수 있습니다. 회사 보안 지침이 외부 AI 서비스에 올려도 되는 자료인지 먼저 확인하세요.

오늘 가져갈 5가지

  1. 일을 나눠 맡길 AI 팀은 파일 몇 개로 만들 수 있다 (.codex/agents, AGENTS.md)
  2. 만들기 전에 설계표를 먼저 받고 사람이 확정한다
  3. 가상 데이터와 정답키로 먼저 테스트한다
  4. 대시보드는 보고만 하고, 결정은 승인·반려·보류로 사람이 한다
  5. 반려한 이유를 지침에 되돌리면 팀이 나아진다
